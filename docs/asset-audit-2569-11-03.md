# ผลตรวจเลขครุภัณฑ์ Excel เทียบทะเบียนจริง

ตรวจวันที่ 3 พฤศจิกายน 2569 จาก `asset/asset-sena1b1.xlsx` เทียบกับ Firestore project `sena-one` จากนั้นเติมเลขเครื่องปรับอากาศห้อง 306 หนึ่งรายการตามคำยืนยันผู้ใช้ โดยสำรองข้อมูลก่อนเขียน ยังไม่แก้เลขขัดแย้งของห้องอื่น

## ขอบเขตและวิธีตรวจ

- ตรวจทุกแถวใน worksheet `การตอบแบบฟอร์ม 1` ช่วง `A1:Z24`: 23 แถวข้อมูล, 22 ห้อง (ห้อง 303 ตอบ 2 แถว)
- ตรวจทะเบียนในระบบครบ 30 ห้อง รวมการหาเลขซ้ำข้ามห้อง
- เทียบช่อง C แอร์, F เตียง/ที่นอน, I ตู้เสื้อผ้า, L ซิงค์, O พัดลม, R เตา, U น้ำ และ X ไฟ
- แยกรายการรวมในช่องเตียง/ที่นอน แยกเลขพัดลมหลายตัว/ช่วงเลข และเทียบรูปแบบที่มี/ไม่มีขีด
- ตรวจช่องสภาพและหมายเหตุเพิ่มเติมแล้ว ไม่พบเลขครุภัณฑ์ที่มีรูปแบบเลขทะเบียนตกอยู่ในช่องเหล่านั้น
- คำว่า “มี”, “ไม่มี”, “ไม่พบ”, เครื่องหมายขีดและ 0 ไม่ถือเป็นเลขครุภัณฑ์
- ไม่ดึงชื่อผู้ตอบและไม่นำผลตรวจเดิมที่ไม่ทราบปีเข้าเป็นประวัติ
- ไม่เดาหมายเลขจากลำดับห้อง และไม่ลบ/เพิ่มหลักตัวเลขเพื่อให้ดูเหมือนเลขมาตรฐาน

## ผลรวม

ก่อนแก้พบเลขในไฟล์ **92 รายการ** เทียบตรงประเภทในทะเบียน **86 รายการ** และรอตรวจสอบ **6 รายการใน 5 ห้อง** หลังผู้ใช้ยืนยันและเติมเครื่องปรับอากาศห้อง 306 แล้ว เทียบตรง **87 รายการ** เหลือข้อขัดแย้ง **5 รายการใน 4 ห้อง**

ตัวเลข **71 รายการ / 16 ห้อง** ในรายงานนำเข้าครั้งก่อนคือ “จำนวนที่เติมใหม่ในครั้งนั้น” ไม่ใช่จำนวนเลขทั้งหมดใน Excel หรือจำนวนเลขทั้งหมดในระบบ

## เลขที่ตรงตามไฟล์ แต่รูปแบบควรตรวจป้ายเพิ่มเติม

รายการต่อไปนี้เก็บตรงตามข้อความในไฟล์ ไม่ได้แปลว่าได้ยืนยันเลขจากป้ายของจริงแล้ว:

- ห้อง 308 พัดลม O9: `4140-005-00001/131` มีจำนวนศูนย์ในกลุ่มรหัสต่างจากเลขพัดลมส่วนใหญ่ในไฟล์
- ห้อง 308 เตา R9: `7310-0004-0001/524` มีจำนวนศูนย์ต่างจากรหัสเตาส่วนใหญ่ในไฟล์
- ห้อง 313 เตา R13: `0731-004-0001/529` ขึ้นต้นต่างจากรหัสเตาส่วนใหญ่
- ห้อง 316 เตา R16: `84106025` เป็นตัวเลขล้วน จึงควรตรวจว่าเป็นเลขครุภัณฑ์หรือเลขเครื่อง

## ตรวจซ้ำจากข้อมูลล่าสุด

```powershell
npm run import:assets -- --audit
```

คำสั่งนี้อ่านข้อมูลอย่างเดียวและสร้างรายงาน `.md`/`.json` ใน `backups/asset-audit-*.{md,json}` โดยเทียบทุกช่องต้นทาง พร้อมจำนวนที่ตรง รอเติม รอตรวจสอบ และเลขซ้ำ รายงานเต็มไม่ถูก commit เข้า Git

เงื่อนไขที่ยังต้องยืนยันไม่ควรถูกแก้ด้วยการรัน `--apply` ซ้ำ เพราะโหมดนำเข้ายังคงเติมเฉพาะช่องที่ขาดและไม่ทับเลขเดิม

การเติมแอร์ห้อง 306 ใช้คำยืนยันเฉพาะเลข/ห้อง/ประเภท ไม่ได้ปิดการตรวจความผิดปกติทั้งหมด:

```powershell
node scripts/import-room-assets.cjs --confirm-category=306:air:4140-005-0001/128 --apply
```

คำสั่งตรวจว่าเลขดังกล่าวมีในช่องของห้องและประเภทที่ระบุจริงก่อนนำเข้า การรันซ้ำไม่เติมซ้ำหรือเขียนทับเลขเดิม ผลสำรวจรายปีที่เป็น snapshot ไม่ถูกแก้ตามทะเบียน
