# สำรวจครุภัณฑ์ประจำปี

## วิธีใช้งาน

- ผู้ดูแลเปิดหน้า **ครุภัณฑ์** เลือกปี พ.ศ. และกด **เปิดรอบสำรวจ**
- ระบบเก็บรายการ ชื่อ และเลขครุภัณฑ์ของแต่ละห้องตามทะเบียน ณ วันที่เปิดรอบ
- ลูกบ้านเปิด **ครุภัณฑ์ → เริ่มสำรวจ** เลือกสภาพทุกชิ้น และระบุสาเหตุหากไม่ปกติ
- สภาพที่รองรับ: ปกติ, ชำรุด, เสื่อมสภาพ, สูญไป, ไม่จำเป็นต้องใช้
- การส่งเป็นการยืนยันผลประจำปี ส่งแล้วแก้ไขไม่ได้ ผู้ดูแลปิด/เปิดรับซ้ำได้เฉพาะห้องที่ยังไม่ส่ง
- ผู้ดูแลเลือกปีเพื่อดูผลแต่ละห้อง ลูกบ้านดูประวัติของห้องที่ตนพักได้
- การแก้ทะเบียนหรือนำเข้าเลขครุภัณฑ์ภายหลังไม่เปลี่ยนผลของรอบเก่า

## นำเข้าเลขครุภัณฑ์

หน้าแอดมินมีปุ่ม **นำเข้าเลขจาก Excel** สำหรับไฟล์รูปแบบ `asset-sena1b1.xlsx`
ระบบอ่านสองเลขพัดลมและแยกเลขเตียง/ที่นอน เติมเฉพาะช่องที่ยังขาด และข้ามรายการที่จับคู่ไม่แน่นอน
เลขเดิมและรหัสประจำรายการจะคงเดิม การนำเข้าซ้ำจะไม่สร้างข้อมูลซ้ำ
ข้อมูลผู้ตอบและผลตรวจเก่าในไฟล์ไม่ถูกนำเข้า

นำเข้าจากเครื่องโดยใช้บัญชี Firebase CLI ที่เข้าสู่ระบบไว้:

```powershell
npm run import:assets -- --dry-run
npm run import:assets -- --apply
```

โหมดปกติเป็นการตรวจเท่านั้น ก่อนเขียนจริงจะสำรองเอกสารห้องเดิมลง `backups/room-assets-*.json`
และใช้เงื่อนไข updateTime ป้องกันการเขียนทับการแก้ไขที่เกิดขึ้นพร้อมกัน
ไฟล์สำรองและ Excel ต้นฉบับไม่รวมใน Git

## การเปิดใช้บนระบบจริง

แบบสำรวจใช้ Firestore transactions และ Security Rules โดยตรง ไม่ต้องเปิด Cloud Functions
เว็บใช้งานจริงอยู่ที่ `https://sena-one.netlify.app/` ให้ deploy กฎและเผยแพร่เว็บบน Netlify:

```powershell
npm run build
firebase deploy --only firestore:rules --project sena-one
```

การอ่านใช้ `equipment_survey_rounds/{year}` และเอกสาร `rooms/{roomId}` ใต้รอบนั้น
คำตอบรายชิ้นอยู่ใน `rooms/{roomId}/responses/{equipmentId}` เพื่อให้ Rules ตรวจครบทุกชิ้นได้
แต่ละคำตอบบันทึกพร้อมเพิ่มจำนวนคำตอบอย่างเป็น transaction และแก้ไขได้ระหว่างที่ยังไม่ส่งผล
การส่งผลสุดท้ายต้องตอบครบทุกชิ้น รอบต้องยังเปิด และผู้ตอบต้องเป็นผู้พักห้องนั้นในปัจจุบัน
หลังส่งแล้ว Rules ป้องกันการแก้ไขทั้งผลรวมและคำตอบรายชิ้น
เอกสารประวัติเดิมที่เก็บคำตอบแบบรวมยังอ่านได้
ลูกบ้านไม่สามารถแก้บทบาทตนเองเป็นแอดมินหรือเขียนผลสำรวจตรงเพื่อข้ามการตรวจสอบได้

## ตรวจสอบ

```powershell
npm test
npm run type-check
npm run test:surveys
npm run test:ui
```

`test:surveys` ใช้ Firestore Emulator โปรเจกต์ `demo-sena-one` และ Java 21 ขึ้นไป
ไม่เชื่อมฐานข้อมูลจริง ทดสอบ transaction ของ client กับ Rules จริง ได้แก่ สิทธิ์ สาเหตุบังคับ
ปีซ้ำ ผลส่งซ้ำ การปิด/เปิดรอบ การส่งพร้อมกัน การปลอมจำนวนคำตอบ
แบบสำรวจ 30 ชิ้น และประวัติที่ไม่เปลี่ยนตามทะเบียน
