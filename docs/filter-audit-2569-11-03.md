# ตรวจ dropdown และตัวกรองทุกหน้า — 3 พฤศจิกายน 2569

## จุดที่แก้

- ประวัติมิเตอร์ในหน้าห้องพัก: dropdown ปีเดิมสร้างรายการผ่าน Portal นอก dialog ทำให้ตัวเลือกถูกกีดกันจากการใช้งานใน dialog เปลี่ยนเป็น native select ภายในหน้าต่าง และแสดงปี พ.ศ.
- รายงานการเงิน: เปลี่ยนสถานะเป็น native select เพิ่มตัวเลือกเกินกำหนด (`overdue`) และแก้ชื่อสถานะทั้งตารางกับ Excel จากที่เดิมแสดง overdue เป็นยกเลิก
- หน้ามิเตอร์: ใช้ native select เลือกห้องพร้อมตัวเลือกห้องทั้งหมด และเพิ่มปุ่มล้างห้อง/คำค้น/สถานะร่วมกัน โดยไม่ล้างค่ามิเตอร์ที่แก้ไว้
- ประวัติมิเตอร์ของผู้ดูแลและลูกบ้าน: ป้องกันผลโหลดปีเก่ามาทับปีใหม่เมื่อเปลี่ยนปีเร็ว และล้างผลเก่าระหว่างโหลด ไม่ให้บันทึกประวัติผู้ดูแลขณะกำลังโหลด
- ปีของบิลและมิเตอร์ฝั่งลูกบ้าน: ใช้ component native select ที่รองรับ theme เดียวกับระบบ
- เพิ่มชื่อควบคุมสำหรับ dropdown สถานะห้อง ชั้น ผู้เช่า สัญญา ใบแจ้งหนี้ และปี เพื่อให้เลือกผ่านคีย์บอร์ด/เครื่องมือช่วยอ่านและทดสอบได้ชัดเจน

## วิธีตรวจและข้อจำกัด

- UI tests ใช้ฐานข้อมูล fixture แยกจากระบบจริง ทดสอบทั้ง desktop/mobile ส่วนชุดตรวจทุกหน้ายังครอบคลุม Light/Dark mode
- ทดสอบเปลี่ยนปีสองครั้งโดยจำลอง Firestore query ของปีเก่าช้า เพื่อยืนยันว่าข้อมูลปีปัจจุบันไม่ถูกทับ
- ตรวจ index metadata ของ Firestore project `sena-one` จริงแล้ว พบ index สำหรับ status ของ contracts/invoices/maintenance และประวัติมิเตอร์อยู่ในสถานะ READY ไม่ได้แก้ index หรือข้อมูลธุรกิจในการตรวจครั้งนี้
- `npm test` ตรวจ logic ของตัวกรอง/ช่วงเดือนเพิ่มเติม `npm run type-check` และ `npm run build` ตรวจการประกอบระบบ
- ผลตรวจรุ่นแก้ไข: regression tests ผ่าน 33 รายการ, UI tests ผ่าน 38 รายการ และ type-check/build ผ่าน
- การตรวจนี้ไม่ใช่การทดสอบทุกบัญชีบน production และไม่ได้สร้าง/ลบรายการจริงเพื่อทดสอบตัวกรอง
- ESLint บางไฟล์เดิมยังมีข้อค้าง เช่น explicit any และกฎ effect จึงไม่ถือว่า repository ผ่าน lint ทั้งหมด
